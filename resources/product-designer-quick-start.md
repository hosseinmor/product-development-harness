# Product Designer Quick Start

برای طراحی از PRD تا تحویل توسعه، این پرامپت کافی است:

```text
با Job Vision Product Development Harness، Product Design انجام بده.

https://github.com/hosseinmor/product-development-harness/blob/main/AGENTS.md

Current PRD:
[لینک یا فایل PRD فعلی]
```

برای شروع، PRD کافی است؛ لازم نیست از ابتدا لینک فیگما یا تنظیمات دسترسی را آماده کنید. اگر فقط بخشی از PRD مدنظر است، محدوده را اضافه کنید. وقتی نوبت اجرای فیگما برسد، Agent باید لینک فایل یا فریم مقصد را بخواهد، دسترسی و امکان ویرایش را بررسی کند و فقط اقدام لازم برای آماده‌شدن اجرا را از شما درخواست کند. اگر مقصد و دسترسی از قبل مشخص‌اند، سؤال تکراری لازم نیست. برای طراحی موجود، ارجاع آرتیفکت فعلی را بدهید تا همان سند به‌روز شود.

نام قبلی «Design Exploration» هم به همین مسیر کامل هدایت می‌شود. اگر فقط بررسی گزینه‌ها می‌خواهید، بنویسید «فعلاً فقط اکسپلوریشن؛ اجرای فیگما و هنداف در این درخواست نیست».

## What happens next

| وضعیت | اقدام | خروجی مورد انتظار |
| --- | --- | --- |
| شروع | Agent، PRD و تجربهٔ فعلی را بررسی و دامنهٔ روشن PRD را بدون تأیید دوباره استفاده می‌کند. | صورت‌بندی مسئله و وایرفریم سادهٔ قابل مشاهده در محیط خود Agent برای مقایسهٔ مسیرهای مهم |
| انتخاب مسیر | شما مسیر را انتخاب یا اصلاح می‌کنید؛ Agent فلو و حالت‌ها را بررسی می‌کند و تصمیم‌های لازم محصول را با پیشنهاد دقیق به PM برمی‌گرداند. | مسیر منتخب و تصمیم‌های مؤثر روشن |
| اجرای فیگما | Agent در همین مرحله لینک مقصد و آماده‌سازی لازم را درخواست می‌کند؛ پس از تأیید و بررسی دسترسی، طراحی را اجرا و بررسی می‌کند. | فریم‌های قابل پالیش و آرتیفکت هماهنگ با تصمیم‌های توافق‌شده |
| پالیش | شما فریم‌ها را پالیش و برای بررسی برمی‌گردانید؛ پذیرش صریح طراحی موجود بدون تغییر هم معتبر است. | نسخهٔ فعلی فیگما برای بازبینی تطابق |
| بازبینی و تحویل | Agent تغییرات مؤثر و تطابق با PRD را بررسی و همان آرتیفکت‌ها را به‌روز می‌کند. | Figma بررسی‌شده + Design Artifact هماهنگ + PRD نهایی یا تغییرات دقیق آن |

وایرفریم‌های مقایسه‌ای ابتدا در همان محیط گفتگو و با قابلیت نمایش موجود ارائه می‌شوند؛ برای این مرحله نیازی به فایل مقصد فیگما نیست. اگر نمایش بصری ممکن نباشد، Agent باید محدودیت واقعی و قدم بعد را توضیح دهد. نیاز زودتر به مشاهدهٔ UI فعلی، جدا از آماده‌سازی مقصد اجرای فیگماست.

انتخاب مسیر موقت با تأیید اجرای فیگما فرق دارد. وقتی اجرای مسیر و مقصد را تأیید کرده‌اید، Agent برای همان محدوده اجازهٔ تکراری نمی‌خواهد.

برای پالیش معمول، توضیح هر تغییر لازم نیست. اگر فلو، تعامل یا قید مؤثری با تصمیم قبلی تعارض پیدا کرده باشد، Agent اختلاف و پیامدش را نشان می‌دهد و عمدی‌بودن و دلیل آن را می‌پرسد. تصمیم تازهٔ طراحی با شماست؛ تغییر رفتار محصول به PM برمی‌گردد. این «بازبینی تطابق طراحی و اثر تغییرات» است؛ سناریوهای رگرسیون، رفتار خود هارنس را می‌سنجند.

## Continue in the same conversation

در همان چت، پرامپت تازه لازم نیست. اعلام «نتیجهٔ جلسهٔ PM این شد…»، «پالیش انجام شد؛ این فریم‌ها را بررسی کن» یا توضیح تغییر موردنیاز کافی است. Agent باید آخرین اسناد و فریم‌ها را بخواند و بخش متأثر را ادامه دهد؛ اگر ارجاع مشخص و قابل دسترسی است، آن را دوباره نمی‌خواهد.

## Transfer to a new conversation or agent

فقط برای انتقال کار به چت یا Agent جدید، می‌توانید از متن زیر استفاده کنید. ارجاع‌های موجود را منتقل کنید و هر بخش هنوز ایجادنشده را حذف کنید؛ این یک شروع دوباره یا پرسشنامهٔ اجباری نیست:

```text
با Job Vision Product Development Harness، همین Product Design را از وضعیت فعلی ادامه بده.

https://github.com/hosseinmor/product-development-harness/blob/main/AGENTS.md

Current PRD:
[لینک یا فایل فعلی]

Current Design Artifact:
[لینک یا فایل فعلی]

Figma:
[فریم‌های فعلی یا برگشتی]

Update:
[نتیجهٔ تصمیم PM، اعلام پایان پالیش، یا تغییر موردنیاز پس از تحویل]
```

در محیط جدید، Agent از آرتیفکت‌های فعلی ادامه می‌دهد و به سابقهٔ چت قبلی وابسته نیست. دسترسی نداشتن به سند یا فیگما باید دقیق اعلام شود؛ ادعای بررسی یا اعمال تغییر بدون دسترسی معتبر نیست.

## Final handoff

تحویل کامل سه بخش دارد: لینک دقیق فیگمای فعلی، مشخصات قابل بازیابی طراحی که با آن هماهنگ است، و PRD نهایی یا تغییرات دقیق قابل کپی آن. آرتیفکت طراحی می‌تواند در محل مستندسازی توافق‌شده باشد؛ لینک خام فریم به‌تنهایی جای مشخصات رفتار را نمی‌گیرد.

پیشنهاد تغییر PRD، تأیید PM و اعمال آن سه وضعیت متفاوت‌اند و باید مشخص باشند. تصمیم محصول حل‌نشده‌ای که روی توسعه اثر اساسی دارد، تحویل را مشروط می‌کند.

Agent باید در هر پاسخ اصلی وضعیت فعلی، اقدام بعدی، مسئول و خروجی مورد انتظار را روشن کند و کار مجاز را بدون دستور مکرر «ادامه بده» پیش ببرد. آمادگی تحویل طراحی به معنی تأیید فنی، QA پیاده‌سازی یا آمادگی انتشار نیست.
