# Product Designer Quick Start

برای پیش‌برد طراحی از PRD تا تحویل توسعه، این متن را در ChatGPT، Claude یا Agent دیگر استفاده کنید:

```text
برای درخواست زیر با Job Vision Product Development Harness، Product Design انجام بده.

https://github.com/hosseinmor/product-development-harness/blob/main/AGENTS.md

Current PRD:
[لینک یا فایل PRD فعلی]

Intent:
[در صورت نیاز، محدودهٔ طراحی]

Figma:
[در صورت مشخص‌بودن، فایل یا فریم مقصد]
```

اگر طراحی کل PRD مدنظر است، می‌توانید Intent را حذف کنید. نام قبلی «Design Exploration» هم به همین مسیر یکپارچه هدایت می‌شود؛ اگر فقط اکسپلوریشن می‌خواهید، صریحاً محدوده را به اکسپلوریشن محدود کنید.

اگر دامنهٔ محصول در PRD فعلی صریح و روشن باشد و با درخواست تعارض نداشته باشد، Agent آن را اعلام می‌کند و بدون تأیید دوباره ادامه می‌دهد. ابهام یا تعارض مالکیت، و تصمیم‌های مهم محصول که در PRD مشخص نشده‌اند، باید روشن شوند؛ Agent به‌جای PM تصمیم نمی‌گیرد.

مسیر به‌صورت رفت‌وبرگشتی ادامه پیدا می‌کند:

1. شناخت PRD و تجربهٔ فعلی، اکسپلوریشن و ارائهٔ وایرفریم ساده برای مقایسهٔ مسیرها.
2. انتخاب و بررسی مسیر کاری؛ آماده‌کردن پیشنهادهای دقیق PRD برای تصمیم‌های لازم PM.
3. پس از تأیید اجرای مسیر و مشخص‌شدن مقصد، Agent طراحی را در Figma اجرا و نتیجه را بررسی می‌کند.
4. شما فریم‌ها را پالیش می‌کنید و برای بررسی برمی‌گردانید؛ اگر طراحی موجود را کافی بدانید، پذیرش صریح بدون تغییر هم معتبر است.
5. Agent فریم‌های برگشتی را با تصمیم‌های توافق‌شده و PRD مقایسه می‌کند. برای پالیش معمول دلیل نمی‌پرسد؛ دربارهٔ اختلاف مؤثر، محل و پیامد تغییر را نشان می‌دهد و عمدی‌بودن و دلیل آن را می‌پرسد. تصمیم جدید طراحی با شماست؛ تغییر رفتار محصول به PM برمی‌گردد.
6. پس از اصلاح و بررسی تطابق، Figma فعلی + Design Artifact هماهنگ + PRD نهایی یا تغییرات دقیق PRD برای توسعه تحویل می‌شوند.

این بررسی، «بازبینی تطابق طراحی و اثر تغییرات» است؛ صرفاً مقایسهٔ پیکسل‌ها یا تست رگرسیون نرم‌افزار نیست. لازم نیست برای ادامه، بررسی PRD یا بازگشت از جلسهٔ PM چت یا Workflow تازه‌ای آغاز کنید.

در هر پاسخ اصلی باید وضعیت فعلی، قدم بعدی، مسئول اقدام و خروجی مورد انتظار روشن باشد. کار مجاز و قابل انجام به دستور مکرر «ادامه بده» نیاز ندارد. در توقف‌های چندروزه یا چند‌هفته‌ای، همان آرتیفکت فعلی جهت کاری، ارجاع‌ها، وابستگی‌ها و قدم بعد را نگه می‌دارد. پس از تحویل هم فقط بخش متأثر باز و همان فایل‌ها به‌روز می‌شوند.

آمادگی تحویل طراحی به معنی تأیید فنی، QA پیاده‌سازی یا آمادگی انتشار نیست. اگر دسترسی فیگما، تصمیم محصول یا جزئیات مهمی باقی مانده باشد، Agent باید آن را صریحاً در تحویل مشروط نشان دهد.
