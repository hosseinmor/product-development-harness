# PM Quick Start

برای ساخت یا ادامهٔ PRD، این متن را در ChatGPT، Claude یا یک Agent دیگر استفاده کنید:

```text
برای درخواست زیر با Job Vision Product Development Harness یک PRD تهیه کن.

https://github.com/hosseinmor/product-development-harness/blob/main/AGENTS.md

Intent:
[مسئله یا تغییر موردنظر]
```

برای **ادامهٔ PRD موجود**، این دو خط را به انتها اضافه کنید:

```text
Current PRD:
[لینک یا فایل PRD فعلی]
```

Agent ابتدا دسترسی به Harness را بررسی می‌کند، سپس محصول پیشنهادی را برای تأیید شما مطرح می‌کند. **لازم نیست نام محصول، لینک Knowledge، روش دسترسی به مرورگر یا دستورهای Workflow را در Prompt بنویسید.** اگر نمی‌تواند فایل‌های ضروری Harness را بخواند، باید اجرا را متوقف کند. روش خواندن مستقیم GitHub یا Clone، وابسته به امکانات محیط است.

اگر MCPهای شرکت در محیط Agent فعال باشند، نالج از اتصال مستندات با جست‌وجوی محدود به محصول خوانده می‌شود؛ لازم نیست لینک نالج یا دستور ابزارها را به پرامپت اضافه کنید. برای ادامهٔ PRD، همان لینک یا فایل مشخص فعلی را بدهید. اگر دسترسی MCP کافی نباشد، Agent مسیر مرورگر داخلی را بررسی می‌کند و فقط آماده‌سازی لازم را می‌خواهد. اتصال‌های فعلی فقط‌خواندنی‌اند؛ با فعال‌شدن ابزار نوشتن، درخواست صریح PM برای انتشار/به‌روزرسانی از طریق MCP انجام و نتیجه بررسی می‌شود. تا آن زمان، فایل و متن آمادهٔ ثبت دستی تحویل داده می‌شود. [راهنمای اتصال](https://mcp.jvoffice.ir/)

خروجی پیش‌فرض یک فایل `.md` به‌روز است که در محیط‌های پشتیبانی‌کننده با **Preview خوانا و فقط‌خواندنی** نمایش داده می‌شود؛ در هر Clarification همان فایل تغییر می‌کند. PM برای بازبینی نیازی به ویرایش Markdown ندارد. هنگام تحویل نهایی، Agent **هم لینک همان فایل و هم کل Markdown خام یکسان با آن را در یک بلوک کد** ارائه می‌کند و صریح می‌گوید: «برای دیدن PRD روی لینک فایل کلیک کن؛ برای کپی Markdown از دکمهٔ کپی بلوک کد استفاده کن»؛ اگر دکمه وجود نداشت، متن بلوک را انتخاب و کپی کنید. بلوک باید Frontmatter، Headingها، جدول‌ها و `Harness Pilot Evaluation > Clarification Record` را هم داشته باشد تا مستقیماً در **ویرایشگر Markdown/Source گیت‌لب** Paste شود. **GitLab Wiki Path** جداست. اگر محیط Preview یا لینک فایل ندارد، Agent باید محدودیت را بگوید و قابلیت‌های موجود را دقیق معرفی کند. Agent برای ساخت PRD جدید سراغ PRDهای قدیمی GitLab نمی‌رود و مسیر انتشار را از مسیر حوزهٔ مالک در Product Knowledge می‌سازد. آماده‌شدن سند به معنی انتشار نیست. با درخواست «در ویکی منتشر کن» و دسترسی نوشتن MCP، Agent همان محتوا را ثبت و پس از بررسی، لینک صفحه را می‌دهد؛ اگر از ابتدا همین انتشار را خواسته‌اید، درخواست دوباره لازم نیست. در نبود ابزار نوشتن، انتشار دستی می‌ماند.

ارزیابی داخلی پایلوت در انتهای همان سند، جمع‌شده و کوتاه نگه داشته می‌شود. در گفت‌وگوی عادی تکرار نمی‌شود و تمام تصمیم‌های لازم محصول در بدنهٔ PRD هستند.

برای ادامهٔ طراحی از PRD تا فیگما و تحویل توسعه، از [Product Designer Quick Start](product-designer-quick-start.md) استفاده کنید. اگر طراحی نیاز به تغییر رفتار محصول پیدا کند، پیشنهاد مشخص تغییر PRD برای تصمیم شما برمی‌گردد؛ تأیید طراحی به‌تنهایی جای تصمیم PM را نمی‌گیرد.
